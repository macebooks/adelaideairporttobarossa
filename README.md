# adelaideairporttobarossa.com.au

Private car transfers between Adelaide Airport (ADL) and the Barossa Valley. Astro static site
served by a Cloudflare Worker, with a booking endpoint that emails the business and auto-replies to
the customer. Project layout and Worker mirror the `Barossataxi` project.

## Layout

```
src/pages/index.astro     the one-page site (poster build, inline SVG, no raster photos)
src/pages/privacy.astro   /privacy
src/pages/terms.astro     /terms
src/pages/404.astro       404 (noindex, no canonical)
src/pages/sitemap.xml.ts  /sitemap.xml, generated at build time (lastmod from git)
src/layouts/Legal.astro   shared shell for the legal + 404 pages
worker/index.ts           www -> apex 301, POST /api/booking, static-asset fallthrough
public/                   robots.txt, _headers, icons, assets/
scripts/audit.mjs         headless audit behind `npm run audit`
legacy/                   superseded builds and unused Build-A photography (not deployed)
```

## Commands

```bash
npm install
npm run dev        # Astro dev server (no Worker, so /api/booking is absent)
npm run build      # → dist/
npm run serve      # wrangler dev on :8787 — the real stack, Worker + assets
npm run audit      # headless SEO/a11y/layout audit against :8787
npm run deploy     # astro build && wrangler deploy
```

`npm run serve` is the one that matters before shipping: the booking form only exists behind the
Worker.

## Configuration

Non-secret config lives in `wrangler.toml` under `[vars]`:

| Var | Purpose |
|---|---|
| `EMAIL_FROM` | SMTP2GO sender. Needs valid SPF/DKIM. |
| `EMAIL_CC` | Comma-separated list; every address gets the booking notification. |
| `EMAIL_REPLY_TO` | Where a customer's reply to the auto-reply lands. |

The API key is a secret, never a var:

```bash
npx wrangler secret put SMTP2GO_API_KEY
```

For local runs, copy `.dev.vars.example` to `.dev.vars` (gitignored) and put the key there.

## Booking endpoint

`POST /api/booking` with JSON `{name, email, phone, flight?, date, passengers?, dropoff?, notes?}`.

- honeypot field `website` — if filled, returns 200 and sends nothing;
- 3 requests per minute per IP, then 429;
- validates required fields, email format, field lengths and the drop-off whitelist;
- emails the business (Reply-To the customer) then auto-replies to the customer (Reply-To the
  business inbox);
- returns `{success:true}` or `{error:"…"}`, which the page renders inline.

## Deployment

`npm run deploy` pushes from your machine. For continuous deployment, the repo
(`macebooks/adelaideairporttobarossa`) is connected to the Worker through **Workers Builds**:
Cloudflare dashboard → Workers & Pages → `adelaideairporttobarossa` → Settings → Build.

| Setting | Value |
|---|---|
| Production branch | `main` |
| Build command | `npm run build` |
| Deploy command | `npx wrangler deploy` |
| Root directory | `/` |

The build command is not optional. `dist/` is gitignored, so a deploy without it would ship a
Worker whose `ASSETS` binding points at nothing.

Secrets do not travel with the repo. `SMTP2GO_API_KEY` must be set on the Worker itself
(Settings → Variables and Secrets, or `npx wrangler secret put`), otherwise `/api/booking`
returns 500 on every deploy.

Non-production branches get preview URLs on `workers.dev`. Every page carries an absolute
canonical pointing at the apex domain, so a previewed copy will not compete with the live site in
search.

## `www`

The Worker 301s `www.adelaideairporttobarossa.com.au` to the apex, before any other handling. The
canonical is the apex, so the `www` form must redirect rather than serve a second copy.

**Three things have to be true, and the redirect fails silently if any one is missing:**

| Where | What | If missing |
|---|---|---|
| Cloudflare DNS | proxied record for `www` | `www` does not resolve at all |
| `wrangler.toml` `routes` | `www.…/*` pointed at this Worker | `522`: reaches Cloudflare, finds no Worker, times out looking for an origin |
| `wrangler.toml` `run_worker_first` | `true` | `200`: the asset store answers `/terms` before the script runs, so www serves a duplicate of the site |

The apex is bound separately as a Worker **Custom Domain**, managed in the dashboard rather than in
`wrangler.toml`. `www` is a plain route because its DNS record already existed and a route attaches
to it without the override prompt a second custom domain triggers.

`run_worker_first` is the expensive part of this: the Worker now runs for every request rather than
only for paths with no matching asset. That is fine at this size, and the option is path-scoped
only when given a glob list while this redirect keys on hostname, so it has to be all requests. The
alternative is a dashboard Redirect Rule, which fires at the edge without invoking a Worker but
lives outside the repo.

Verified live: `www/terms?x=1` → `301` → `https://adelaideairporttobarossa.com.au/terms?x=1`.

## Sitemap

`/sitemap.xml` is generated by `src/pages/sitemap.xml.ts`, not shipped as a static file. Each URL's
`<lastmod>` comes from the last git commit that touched that page's source, falling back to the
file mtime and then the build date. That keeps an unchanged page's date stable across deploys —
a `lastmod` that bumps on every build is noise, and Google starts ignoring the field.

Adding a page means adding a line to `ROUTES` in that file. `/404` is deliberately excluded: it is
`noindex` and carries no canonical.
